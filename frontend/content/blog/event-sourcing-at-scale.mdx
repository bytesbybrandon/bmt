When you're ingesting 10 million records a day from 200+ heterogeneous sources, **event sourcing isn't a pattern—it's survival.**

## The Constraint Landscape

- **200+ MLS providers**, each with their own schema, rate limits, and reliability
- **Sub-50ms P99** on consumer read APIs
- **Dual write**: PostgreSQL (transactional) + OpenSearch (analytics)
- **Schema evolution** without downtime
- **Exactly-once** semantics despite source flakiness

## Architecture

```
┌─────────────┐     ┌─────────────┐     ┌──────────────────┐
│   CDC       │────▶│  Event Bus  │────▶│  Projection      │
│  (Debezium) │     │  (Kafka)    │     │  Workers         │
└─────────────┘     └─────────────┘     └────────┬─────────┘
                                                  │
                    ┌─────────────────────────────┼─────────────┐
                    ▼                             ▼             ▼
              ┌───────────┐               ┌───────────┐  ┌───────────┐
              │ PostgreSQL│               │ OpenSearch│  │  Redis    │
              │ (Source   │               │ (Search/  │  │  (Cache/  │
              │  of Truth)│               │  Analytics)│  │  Session) │
              └───────────┘               └───────────┘  └───────────┘
```

## Critical Decisions

### 1. CDC Over Polling
Debezium on SQL Server CDC → Kafka. No custom pollers, no missed updates, no schema coupling.

### 2. Event Schema = Contract
Every event is Avro-registered. Consumers validate on read. Producers evolve backward-compatibly.

### 3. Idempotent Projections
Each projection worker tracks its Kafka offset + event hash. Reprocessing is free and safe.

### 4. Dual-Write via Transactional Outbox
PostgreSQL `outbox` table → Kafka Connect → OpenSearch. No distributed transactions.

## What I'd Do Differently

1. **Start with OpenSearch ISM** (Index State Management) earlier—manual ILM policies bit us
2. **Invest in Kafka Streams** for lightweight transformations instead of custom workers
3. **Add event replay tooling** from day one—debugging production issues without it is painful

## The Takeaway

Event sourcing at scale isn't about "event-driven architecture" as a buzzword. It's about **making the immutable log the single source of truth** so every downstream system—search, analytics, cache, audit—is a deterministic projection.

When the next provider adds a field, when OpenSearch changes its mapping, when you need a new report: you replay from the log. The system *remembers*.
