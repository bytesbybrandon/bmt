The industry is obsessed with **prompt engineering**. I'm obsessed with **prompt elimination**.

## The Prompt Trap

Every week there's a new "prompt pattern":
- Chain-of-thought
- Tree-of-thought
- ReAct
- Reflexion
- Self-consistency
- AutoGPT, BabyAGI, etc.

They all share one flaw: **they treat the LLM as a reasoning engine**.

But LLMs are *probabilistic token predictors*. They don't "reason"—they continue patterns. When the pattern breaks (ambiguous input, missing context, token limit), the output degrades unpredictably.

## What Actually Works: Typed Guards

```typescript
// Instead of "be careful with user data"
// We write:

interface UserDataAccess {
  require: 'USER_CONSENT_GRANTED'
  scope: 'READ' | 'WRITE'
  fields: string[]
}

const guard = (signal: Signal, ctx: Context): GuardResult => {
  if (signal.type === 'TOOL_CALL' && signal.tool === 'user.data') {
    const consent = ctx.consents.get(signal.payload.userId)
    if (!consent?.granted) return { pass: false, reason: 'CONSENT_REQUIRED' }
    if (!signal.payload.fields.every(f => consent.fields.includes(f))) {
      return { pass: false, reason: 'FIELD_EXCEEDS_SCOPE' }
    }
  }
  return { pass: true }
}
```

This isn't a prompt. It's **TypeScript that runs before the LLM sees anything**.

## Hierarchical State Machines > Prompt Chains

```
AGENT
├── IDLE
├── PLANNING
│   ├── DECOMPOSE_TASK
│   ├── VALIDATE_PLAN (guard: plan.passesAllPreconditions)
│   └── COMMIT_PLAN
├── EXECUTING
│   ├── STEP_N
│   │   ├── PRE_GUARD (typed)
│   │   ├── TOOL_CALL
│   │   ├── POST_GUARD (typed)
│   │   └── EMIT_PROGRESS
│   └── CHECKPOINT (event-sourced)
└── COMPLETE / FAILED / RECOVERING
```

Each state has **typed entry/exit guards**. The LLM only operates *inside* `STEP_N`—everything else is deterministic code.

## Event-Sourced Recovery

```
Session interrupted at STEP_3 (network failure)
         │
         ▼
Replay event log from CHECKPOINT_2
         │
         ▼
Rehydrate exact state (variables, tool results, context)
         │
         ▼
Resume at STEP_3 — zero context loss, zero token re-spend
```

This is impossible with pure prompt chains. The conversation history *is* the state, and it's fragile.

## Model Context Protocol (MCP) Integration

Reactive Skills implements MCP natively. Tools aren't "functions the LLM calls"—they're **signal handlers with typed contracts**:

```typescript
const mcpServer = createMCPServer({
  tools: [
    {
      name: 'code.search',
      schema: CodeSearchSchema,  // Zod schema = guard
      handler: async (input, ctx) => {
        // Typed input, typed output, audited
      }
    }
  ]

```

The LLM *never sees raw tool definitions*. It sees **signal schemas** that match the guard types.

**Stop asking "how do I prompt this better?"**  
**Start asking "what typed invariants must hold?"**

The LLM becomes a **constrained generator inside a verified envelope**. The envelope is code. The code is testable, auditable, and recoverable.

That's not prompt engineering. That's **software engineering with an LLM inside**.
